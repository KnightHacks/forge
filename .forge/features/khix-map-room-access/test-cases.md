# KHIX Map Room Access Test Cases

- TC01: Missing config reads disabled/empty. Save a list with restrictions off; reload preserves it without enabling restrictions. Save toggle and list together; no partial state appears.
- TC02: Trim and uppercase room numbers, trim names, reject duplicate building/room entries and invalid building IDs; the same number in different buildings is valid.
- TC03: Non-officers cannot save. Participant reads are session-scoped, unavailable without authentication, and available only to confirmed/checked-in hackers from the event’s first local calendar day. Missing, pending, accepted, waitlisted, denied, and withdrawn applications remain forbidden.
- TC04: Fresh and upgrade migrations create defaults and the FK. Deleting a hackathon removes its configuration; failed transactional writes leave prior config unchanged.
- TC05: Bathrooms stay blue through restrictions, activity, and selection. Unbooked rooms stay striped with their verified numbers visible. With organizer restrictions off, only the event roster is available; enabled empty config restricts event rooms too.
- TC06: Idle is gray. Live is bright green. Upcoming exactly 60 minutes away is green outlined; one millisecond later is gray. Ended events do not highlight. Live wins over overlapping upcoming events regardless of order/selection.
- TC07: HEC and L3Harris aliases plot at the HEC footprint. Locate includes HEC's joined first-floor plan. Verified numbers resolve to that floor; unverified positions use a building-level fallback with a clear message.
- TC08: Building selection enters its first supported floor; locating a room searches available geometry, opens its floor, and preserves access colors.
- TC09: Loading configuration shows a pending state. Initial failure offers Retry and does not assume unrestricted access. Refetch failure retains last good policy. SDK contracts reject invalid responses.
- TC10: Blade save errors retain edits; successful saves refresh configuration. Keyboard controls, long names, 60 rows, reduced motion, desktop and 320px layouts remain usable without document overflow.
- TC11: Multiple live rooms retain green highlighting, numbers, accessible activity descriptions, and event selection without repeated room-level LIVE badges. Building dropdowns use Blade's shared Select; initial and refresh errors use the established map message and overlay surfaces.
- TC12: Multiple events do not add circular markers to the campus overview. Building LIVE counts and activity highlights remain, and selecting an event from Explore events still opens its mapped room or building.
- TC13: At desktop and 320px widths, the event card shares the map overlay surface and portal typography. Its in-card X has an accessible Close event label and a 44px target. Closing removes the details; Explore events can reopen them. Time/location/floor remain readable, and long descriptions scroll without hiding the close control.

- TC14: Both confirmed and checked-in stay locked one millisecond before Friday midnight Orlando time, unlock exactly at midnight, and remain available afterward. DST and invalid timing are covered by the shared policy tests. The direct route does not mount the map or request configuration while locked.
- TC15: Map appears directly below Hacker’s Guide in the desktop rail and mobile drawer. The locked entry has a lock icon and explanation; compact navigation preserves 44px mobile targets and scrolling for short viewports.
- TC16: At 320px and 390px widths, building/floor navigation and map utilities retain 44px targets; the room key is initially collapsed and the gesture hint is hidden. Opening the room key, location form, or event drawer closes the other secondary surfaces. Escape and close controls return focus appropriately.
- TC17: Live/Upcoming filters work within the same drawer on campus and indoors. Selecting an event replaces the list with bounded, scrollable details; Events returns to the list and Close collapses the drawer. Loading, error/retry, empty, and locked states remain usable.
- TC18: Pure camera tests verify portrait and desktop fitting, asymmetric control insets, zoom limits, rotated bounds, invalid measurements, and indoor pan limits. Manual zoom/pan survives drawer resizing; pinch-out stops at the floor overview. Touching during camera animation starts at the displayed position rather than jumping to the animation destination.
- TC19: Every one of the 43 requested room identities appears in the directory. Thirty-nine resolve to the correct floor and source geometry with or without a leading zero. HEC 103/110/111/125 remain explicitly unplaced; no borrowed polygons or false indoor position markers are created.
- TC20: SU names, 218ABCD and 316ABCD resolve to whole-ballroom anchors; single sections remain distinct. Room permission aliases respect those boundaries. SU 232 uses its existing Starbucks anchor as a point marker; ENG2 302 resolves to floor 3. Schedule parsing recognizes all six buildings and preserves unknown-location fallbacks.
- TC21: With organizer restrictions off or with an explicit organizer entry, an unbooked room stays striped/unavailable, retains its verified number but no optional name or activity highlight, and cannot open event details. All verified aliases remain on a shared outline, but an unbooked alias's event cannot highlight it.
- TC22: Unverified room envelopes are unavailable; bathrooms and circulation retain their existing treatment. Source numeric labels and wayfinding remain visible; captions for unbooked room names and temporary review IDs are hidden. Locating an unbooked number falls back to the building with a clear explanation.
