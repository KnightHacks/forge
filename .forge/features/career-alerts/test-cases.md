# Career Job Alerts and Digests Test Cases

Status: Accepted for #650

Use the API package for service proof. Pure matching can run without a database.
Use disposable PostgreSQL for preference writes, ownership, and the recipient
query. Use a fake Discord gateway for membership changes and failures.

| Case | Action                                                                                                                                                                                                                     | Expected observation                                                                                                                             |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1   | Create, list, edit, and remove a preference for a signed-in member.                                                                                                                                                        | Only that member's preference rows change. Custom display wording survives a round trip.                                                         |
| P2   | Try an invalid city, a custom value that normalizes to empty, a duplicate target on create or edit, or a write to another member's row.                                                                                    | Invalid values are rejected. Duplicates return conflict. A foreign row is treated as missing.                                                    |
| M1   | Save Google and Orlando internship alerts. Match a Seattle Google internship, an Orlando internship at a different company, a job matching both, and an Orlando new-grad job.                                              | The first three jobs match once apiece. The new-grad job and a member with no preferences produce no match.                                      |
| M2   | Match company keys and normalized company Other. Match a city among multiple locations, a U.S. remote location, and a custom phrase in unknown source text. Try LA against Atlanta and a city against an unknown location. | Each supported match succeeds. The partial-word and unclassified-city cases do not match.                                                        |
| M3   | Resolve matching member IDs to Discord IDs, including an invalid or missing Discord identity.                                                                                                                              | The lookup emits only valid numeric IDs, in stable order and without duplicates.                                                                 |
| D1   | Enable internship digests, repeat the request, then disable them.                                                                                                                                                          | The internship flag is saved before the grant or revoke. Repeating the request keeps the same saved choice. The new-grad flag stays unchanged.   |
| D2   | Fail storage, then separately simulate an invalid identity, missing role configuration, and a Discord failure after saving.                                                                                                | A failed save makes no Discord call. Post-save failures preserve the flag and report `roleSynced: false`.                                        |
| D3   | Start with a missing role grant, a stale role grant, and a current subscriber. Simulate a failed update among otherwise successful updates.                                                                                | Repair grants and revokes the appropriate roles, preserves the current subscriber, reports the failure, and can retry the failure.               |
| D4   | Fail a guild member page after earlier pages succeeded.                                                                                                                                                                    | Repair reports the read failure without issuing grants or revokes from partial data.                                                             |
| D5   | Configure both tracks with one role, or configure one with a Blade-linked permission role.                                                                                                                                 | The choice saves with `roleSynced: false`. Repair rejects the configuration before reading guild members. Neither path grants or revokes a role. |
| D6   | Opt in two member records for one Discord ID, then opt out each record in turn.                                                                                                                                            | The account keeps its role until the last opted-in record is off.                                                                                |

Before local PR review, run the focused cases, check the affected API and cron
imports, and run `pnpm verify:precommit` from the repo root.
